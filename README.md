# Бесплатный новостной Telegram-бот

Раз в сутки берёт свежую новость из RSS-лент (список в `feeds.txt`) и постит в ваш канал: эмодзи, заголовок, короткая выдержка и ссылка на источник. Без ИИ, без платных API, без своего сервера. Работает на бесплатном GitHub Actions.

## Настройка

1. Создайте бота у @BotFather, сохраните токен. Добавьте бота в канал **администратором** с правом публикации.
2. Загрузите все файлы в репозиторий GitHub. Файл `news.yml` должен лежать по пути `.github/workflows/news.yml`.
3. **Settings → Secrets and variables → Actions → Secrets** создайте два секрета:
   `BOT_TOKEN` (токен от BotFather) и `CHANNEL_ID` (`@имя_канала` для публичного канала или число `-100…` для приватного).
4. **Settings → Actions → General → Workflow permissions** выберите *Read and write permissions*
   (нужно, чтобы бот сохранял список опубликованных ссылок).
5. Вкладка **Actions → Daily news post → Run workflow**, поставьте галочку `dry_run` и запустите. В логе увидите пример поста, в канал ничего не уйдёт. В логе также видно, какие ленты работают.
6. Запустите ещё раз без галочки: пост появится в канале. Дальше бот сам работает каждый день в 10:07 по Екатеринбургу (меняется в строке `cron` файла `news.yml`).

## Настройка источников и вида поста

- `feeds.txt` — список лент. Добавляйте и удаляйте строки. Нерабочая лента пропускается.
- Переменные (**Settings → Secrets and variables → Actions → Variables**, необязательно):
  `POSTS_PER_RUN` (сколько постов за раз, по умолчанию 1), `MAX_AGE_HOURS` (не брать новости старше N часов, по умолчанию 48), `MAX_CHARS` (длина выдержки, по умолчанию 350).
- Правила выбора эмодзи лежат в `EMOJI_RULES` в начале `bot.py`.

## Запуск на своём компьютере (для проверки)

```bash
pip install -r requirements.txt
DRY_RUN=1 python bot.py
```

## Ограничения

- Бот не пишет новость своими словами: он берёт заголовок и начало описания из RSS. Качество зависит от лент.
- Повторов не будет: ссылки хранятся в `posted.db` и сохраняются в репозиторий после каждого запуска.
- Расписание GitHub выполняется «примерно вовремя», запуск может задержаться на несколько минут.
- Если в публичном репозитории 60 дней не будет никаких коммитов, GitHub отключит расписание. Коммиты с `posted.db` после каждого поста этому мешают.
